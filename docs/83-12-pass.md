## Hardening shipped (server)
- `api/chat/common.php`: shutdown logger registered FIRST (covers chat_schema
  crashes too): any PHP fatal in the chat chain is written to `chat_error_log`
  AND returned as JSON `{"message":"Server error: …"}`.
- `api/chat/diag.php?key=…` (key-gated, not linked in-app): phpversion, chat
  table presence, last 25 chat_error_log rows — next live failure self-reports.
- `client.ts chatStartDMByUsername`: failures now carry the server reason;
  the bubble shows `⚠ not sent — <reason>` for conversation-open failures too
  (previously bare, no reason).

## Client UX fixes
- **Profile loader** (`profile/[username].tsx`): `BreathingContent` — a
  profile-shaped skeleton (avatar circle, name/bio bars, stat chips, post
  rows) that slowly inhales/exhales. The icon-only BreathingCrescent is gone.
- **Back from profile → returns to the chat**: tapping the avatar/name in a
  DM no longer closes the inbox; it stores `dl_inbox_reopen` (storage) and the
  community screen reopens the inbox on that exact thread on mount (and the
  stack-kept screen simply stays open). Key cleared on close/unmount.
