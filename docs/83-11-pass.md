## 1. "Message not sent" — what was actually wrong
Two live-only killers, both now fixed at the source:
1. **PHP 7.4 fatals**: `chat_kind()`/`chat_title()` call `str_starts_with()` — a PHP 8 function. On a cPanel server still running PHP 7.4, every chat call that touches them dies with an **empty 500**. The client could only show "⚠ not sent". → **Polyfills added** (str_starts_with/str_ends_with/str_contains) — chat now runs on PHP 7.4+.
2. **Silent server crashes**: chat endpoints had no top-level error handler — any fatal returned an empty body the client couldn't explain. → **Fatal-to-JSON catchers** on `send.php` + `start_username.php`: any crash now returns `{"message": "Server error: <reason>"}` which renders in the bubble. If anything ever fails again, the bubble tells us exactly what — no more mystery.
3. `blocks_ensure` (block check) can no longer kill start/send.
4. Client: **one silent retry** (1.8 s) before failing, and a bare failure now still says something (`No connection` / `Server error (HTTP 500)`).
