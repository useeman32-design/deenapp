# Pass 83-13 — THE "not sent" ROOT CAUSE (2026-09-08)

## Caught red-handed by the 83-12 diagnostic logger
Owner retested after pulling; the bubble showed `⚠ not sent — Server error
(HTTP 500)`. `api/chat/diag.php` on live returned the exact fatal, repeatedly:

    SQLSTATE[42S22]: Column not found: 1054 Unknown column 'c.kind'
    in conversations.php:12 and start_username.php:39

Live also revealed: **PHP 8.3.33 / LiteSpeed** (the old PHP-7.4 theory was
wrong; polyfills harmless).

## Root cause
Production carries a `chat_conversations` table from an older release with
only (id, created_at). `CREATE TABLE IF NOT EXISTS` is a no-op on an existing
table, and `chat_ensure_column` covered only status/requested_by — so every
query using `c.kind`/`c.title` threw. My replica never caught it because the
DB dump had NO chat tables (fresh CREATE path).

## Fix (deenlink-api e6ba5b4, server-only — no bundle change)
- `chat_schema()` now ensures EVERY column the chat queries use:
  conversations(kind, title, created_at), participants(joined_at,
  last_read_at), messages(sender_id, body, media_url, created_at),
  presence(last_seen), typing(expires_at). Idempotent; heals on first request.
- Removed the duplicate per-file fatal handlers in send.php/start_username.php
  (common.php's logger already answers; the copies double-printed the body).

## Verification (replica, PHP 8.4 + live-mirror DB)
Recreated the stale table (id, created_at only) → start_username returned the
exact live 500 (SQLSTATE 42S22, logged to chat_error_log) → deployed fix →
same request auto-healed the table (kind/title/status/requested_by added,
existing row defaulted kind='dm') → send ✓ conversations ✓ messages history
intact ✓.

## Lesson recorded
Replica DBs must test BOTH paths: fresh tables AND stale-schema tables,
because CREATE IF NOT EXISTS hides upgrades.
